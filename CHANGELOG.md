# Changelog

All notable changes to ShrinkRay are documented here. Releases are tagged in git; the GitHub release for each tag carries the same notes.

## [Unreleased]

### Removed

- **The bare-metal systemd unit is removed; the container is the deployment path** : `deploy/shrinkray.service` (and the `deploy/` folder with it) assumed a uv-from-source install on a user's home directory — a path nothing documents as supported anymore now that the ghcr image is the NAS shape. The README's headless section points at the container run, and docs/docker.md records the decision. Nothing consumed the unit file (no CI, test or build reference).

- **The CLI is one product: `encode`, `plan`, `serve`, `retained`, `doctor`** (issue #202): the nine-command surface was sediment from three earlier products, and three of the commands contradicted the product contract — `encode` without `--quality` ran an unmeasured fixed-preset encode that could take a library file's path, `plan --fixed` advertised a mode that did not exist, and `watch-mode` was a second watcher beside the resident app's that could not share its database. Removed: the fixed-preset encode path (`encode` is always VMAF-measured now; `--quality` is accepted and ignored, `--fixed` too), `scan` (the catalog wrote `movies.txt`/`output.csv` artifacts no product surface reads; scanning stays the resident backlog's first job), `report` (the CLI command AND the dashboard's `/report` route — the fossil per the issue's comment; the provenance surface is the dashboard's per-title chain), `compare` (its provenance chain is the dashboard's), and `watch-mode` (the resident `serve` owns watching). `app` is renamed to `serve` with `app` kept as a hidden alias, so the container entrypoint keeps working. `doctor` stays as the maintainer's health check (per the issue's comment, it is debugging and stays undocumented in PRODUCT.md).

### Added
- **The resident mode verifies every encode** (issue #235): the watcher and the job worker now measure the full output against the source after each encode and record the VMAF on the encode row; the number is exposed through the API and the movie detail's history (VERIFIED column). A job payload can still opt out with `verify: false`.
- **The installer quick-start is pinned by a drift guard** (issue #381): issue #322's fix (#344) shipped without the test its acceptance criterion asked for - nothing failed if install.ps1 named a removed command or a hidden alias again. tests/test_container.py now reads the script and asserts every named command exists in the CLI, with the removed `scan` command and the hidden no-op `--quality` flag pinned explicitly.
- **Tracks are kept by default** (issue #297): the language filters now ship empty — every audio and subtitle track survives an encode, as PRODUCT.md's 1:1 promise states. The reference preset's language lists remain available as an opt-in filter (`handbrake.audio_languages` / `handbrake.subtitle_languages`, editable in `shrinkray setup`); an operator who relied on the old default filter must set it explicitly.

- **docs/encode-decision.md documents the ab-av1 measurement reference** (issue #310): what matches (the vmaf_v0.6.1 model, the pooled per-window mean, the mean-of-means decision statistic, the single-filtergraph comparison), every deliberate deviation with its reason (the 10-90% sample windows, the 10 s duration-cut windows, HDR tone-mapped to SDR before scoring, the probe/final preset split - believed safe, not measured, bar detection, which ab-av1 leaves to the operator, the full-file quality verification), and pointers to the search-side differences (#313, #314, #315, #316, #317). Every number and code reference checked against the code.
- **A mechanical check keeps the docs' routes and commands aligned with the code** (issue #304): every \`/api/...\` path and \`shrinkray <command>\` the user-facing docs name must be a registered FastAPI route (method included - \`POST /api/jobs\` is not saved by \`GET /api/jobs\` existing) or a registered typer command, read from the app objects rather than grepped from source. CHANGELOG is excluded by file (history names removed surfaces on purpose), and a sentence asserting non-existence is not a claim. The test caught three live stale claims on its first run (PRODUCT.md's removed cancel/watch routes, tui.md's removed \`watch\` command) and was proven to fail on both of #238's example removals.
- **`shrinkray setup`, the terminal UI that configures and controls** (issue #252): one Textual screen for everything an operator may change — the required VMAF, the final and probe presets, the probe density, the thread cap and stall watchdog, idle priority, the eligibility floors and extra codecs, the file extensions and backlog-on-start — plus the pause/resume switch where the resident app keeps its data. Values go through the same schema as a loaded config, so a value the app would refuse (a 720p floor, a non-number) is shown and never written; a change to a setting in every stored plan says that it re-measures the library before it is saved; the file is written atomically and keys the screen does not show stay untouched. The resident app applies a save at its next file. In the container: `docker exec -it <container> shrinkray setup`, or the console banner's first line. New dependency: `textual`. The dashboard still only observes.

- **The required VMAF is a setting: `quality.target_vmaf`** (issue #252): the floor was only a constant (96) that each entry point defaulted to, so the resident app could not be given another one and the terminal UI had nothing to edit. The key (1-100, default 96) is now the default of `encode` and `plan` (an explicit `--target-vmaf` still wins), the backlog jobs and the watcher, which re-reads it at the next file. It is part of the stored plan fingerprint, so changing it re-measures the library.

- **The container console prints what to type** (issue #251): opening a shell in the container (Unraid's Console button, `docker exec -it <container> sh`) now prints a short manual: whether the resident server runs, how to encode one file, list retained originals, change settings and pause or resume, and the dashboard's token. Every line is computed from the container's state and names only commands that exist (a test fails the day they drift apart). It prints once per console, for interactive shells only, so `docker exec <container> <command>` output stays clean.

- **The resident app can be paused, and a manual encode pauses it** (issue #250): a `paused` file in the data folder (`touch /data/paused` in the container) holds the watcher and the backlog's plan and encode jobs before their next file, survives restarts, and resumes when removed; the terminal UI will be its switch. A `shrinkray encode` run beside the resident app (the container console's single-file case) leaves a marker for its whole run, so the watcher and the backlog yield instead of competing for the CPU; the marker records the process start time, so a crash, a closed console or a container restart that reuses its pid can never leave the app paused. A running encode always finishes. `/api/status` reports the reason (`paused`) and the dashboard shows it, read-only. In an interactive terminal `encode` now warns that closing it cancels the encode. Scans are not paused.

- **The container generates its dashboard token when none is set** (issue #249): a published container needed `SHRINKRAY_TOKEN` (the app refuses a public bind without one), so every install started by inventing a secret, and an Unraid template would have had to ask for one. With `SHRINKRAY_TOKEN` unset, the server now reads `/data/token` (`SHRINKRAY_TOKEN_FILE`, set by the image only), generating it on first start: 32 random bytes, a file created exclusively with mode 0600 and owned by `PUID`/`PGID`, reused on every later start, never logged. An explicit `SHRINKRAY_TOKEN` always wins; an empty token file is a startup error, never "no authentication"; a native `serve` never generates a secret. The healthcheck reads the same source, the compose file no longer requires the variable, and the release smoke test checks a token-less container turns healthy and still refuses an anonymous request.

- **The encode settings are documented against a reference HandBrake preset** (issue #240): `docs/handbrake-preset-reference.json` is a verbatim export of a working HandBrake preset that handles the non-video half of an encode the way ShrinkRay should (Matroska container, every audio track copied, every subtitle track kept, chapters and metadata preserved), and `docs/encode-settings.md` is the key-by-key contract derived from it — which key we already match, which we deliberately differ on and why (the measured CRF, the probe/final preset split, the HDR encoder, the crop rect, no resolution cap), which we must never adopt (burning subtitles, the deinterlacer, a stereo mixdown), and which are gaps still open (#240: the container is autodetected from the output extension instead of pinned to MKV, `mp2`/`opus` are transcoded instead of copied, the fallback is lossy AAC instead of lossless FLAC, and nothing verifies that audio/subtitle tracks survived). The JSON is a reference artifact, not a runtime dependency: nothing in `src/` reads it, because importing a preset would make its language lists filter tracks invisibly and would let the installed HandBrake version silently rewrite the settings.

- **The resident watcher's output directory is configurable via `$SHRINKRAY_WATCH_OUTPUT`** (issue #193): the resident app hardcoded in-place encoding, so a read-only `/media` (test containers, special setups) crashed the watch thread on its staging folder with no way to point the encodes elsewhere — the operator could mount writable (the default, per #198) but nothing more. The env var points the watcher at a writable volume; the app validates the path at boot (creates it, checks writability) and refuses to start on a bad path, so a typo fails loudly instead of killing the watcher hours later. Zef-X's decision on the issue: writable `/media` by default, the env var for the exceptions.

- **One timeline-based crop detector replaces the two bar measurements** (issue #181): `plan`/`encode` now measure bars with a single keyframe-only cropdetect pass over the whole runtime (`-skip_frame nokey`, the #131 spike's measured ~3 min/hour of runtime), filtered to segments sustained for at least 30 s (counted in seconds, never readings, with a 3-reading floor) and cropped only where every sustained segment agrees — the safe union, so a dark-scene flash or an isolated logo can never shrink the picture. The result is cached per file version in a new `crops` database table (schema v16, keyed by size + mtime), `scan`'s 1/0 flag becomes the cached summary's projection when one exists (the cheap probe stays for never-planned files and scan never runs the expensive pass), and the report's bar note shows the sustained picture-size breakdown (e.g. "1920x800 (60% of the time)") instead of the generic pre-filter wording. Stateless runs (no `--db`) keep the previous sampled-window detector as fallback.

- **`watch` wakes on filesystem events instead of only polling** (issue #176): between passes the loop sleeps on an inotify waiter (Linux) that fires on file creation, close and moves anywhere under a watched root, so a movie that lands in the inbox starts encoding within seconds instead of after the backoff window. The adaptive poll stays the fallback and the reconciler — a wake never bypasses the stability check — and platforms without a supported event API (and every setup error) degrade to exactly today's polling behavior.

### Fixed

- **The resident server stops once** (issue #386): a copy-paste in run_app's finally block called state.shutdown() and logged "app stopped" twice per stop - the second against an already-closed AppState, which made a restart loop read like a double shutdown in the container log. One boot, one stop; a test pins the shutdown count so a future copy-paste fails.
- **The resident app's encode job takes the same per-movie slot as the watcher and a single-file `shrinkray encode`** (issue #336): the job took its encode slot on its own per-run staging directory, a path no other encoder ever locks, so a single-file `shrinkray encode` of the same movie could run beside it. In place, the job now takes the slot on the movie's directory and skips a movie another encoder holds with a busy error; with an output directory it keeps the slot on that directory. A folder- or glob-form `shrinkray encode` still keys its slot on the folder, so it does not exclude the job on a library with one folder per title (#379). Known limitation (#383): a `docker stop` during an encode leaves the lock in the movie's folder, and the restarted server, again pid 1, takes it for a live holder. The boot backlog then skips that movie as busy, and nothing retries it until a boot more than 6 hours later or a change to the file.
- **The resident server is reached through a named seam** (issue #373): `run_app` constructed `uvicorn.Server` inline, so the tests had to patch `uvicorn.Server` — an attribute uvicorn only re-exports from its `__init__`, which made the tests fail with `AttributeError` on a fresh CI session and pass locally on the same commit. The boot call now goes through a module-level `_serve_forever(host, port)` that the tests patch, and a test covers its body (the `Config` it builds and the `run()` it calls), which no test did before.
- **The CLI honours the saved encoder presets** (issue #328): `--encoder-preset` and `--probe-encoder-preset` defaulted to code constants (`3`/`5`) instead of the config, so `handbrake.encoder_preset` / `handbrake.probe_encoder_preset` — the values `shrinkray setup` saves and the resident jobs and watcher already used — were silently ignored by the one-shot CLI. The same saved config produced different encodes depending on which mode ran it. Both options now default to the config value (an explicit flag still wins), and `load_config` returns an explicit `--config` file instead of a config another caller cached first.
- **Docs: the HDR tone-map comment no longer claims validation, and encode-settings.md states the real 10-bit rule** (issue #362): the comment now describes the chain as an SDR-model approximation with #340's measured ~2.9 VMAF footprint (which errs safe), and the VideoEncoder row states the #234 rule - the source's bit depth decides, HDR forces 10-bit.
- **The TUI's language-filter test survives the empty default** (issue #297's follow-up): #297 changed the shipped `handbrake.audio_languages` / `handbrake.subtitle_languages` defaults to `[]`, and the #337 test asserted the old reference lists, so `main` went red on that one assertion. The test now starts from an explicit filter (the upgrade case), asserts the fields render it comma-separated, and pins that clearing a filter writes `[]` rather than silently leaving the old one in place - verified by mutation: with `edited()` skipping empty-list writes, the test fails; without, it passes.
- **HDR sources with black bars can be measured** (issue #307): the VMAF comparison's HDR branch ignored the crop, so a widescreen HDR10 title (2.39:1 content in a 16:9 frame - common in exactly the target libraries) met libvmaf with mismatched frame sizes and its CRF search could not measure it. The reference is now cropped to the encoded geometry BEFORE the tone-map (the bars must not influence the tone-map), and the post-encode verification path is covered by the same fix. Verified on a synthetic HDR10 clip with baked bars: the fixed measurement completes with a plausible score.
- **PRODUCT.md describes the server and the tree that exist** (issue #238): the "Authentication: none today" passage contradicted the file's own auth roadmap (an opt-in token since #36, required for any non-loopback bind; the container generates one since #249) and told an operator the dashboard was always open; the engine-modules evidence line still named the dissolved `quality/encode/watch/jobs/db/app` files from before the #63 layout. Both passages now state the current model. The issue's other five rows (the README's removed POST routes and UI-configure claims, the tui.md note about a removed command, the docker config path) were re-verified against `main` and are already accurate - earlier fixes (#236, #268, #276-era cleanups) landed them.

- **The last preflight mentions are gone from the UI code** (issue #301): a CSS comment in App.svelte and a phrase in api.ts's error-translation note still described the ceremony removed by #239; both are deleted (the CSS block they sat in carried no rules - verified dead), and \`git grep -i preflight -- ui/src\` is now empty.
- **The documented smoke-test command passes when the smoke tests do** (issue #295): `tests/test_smoke.py` told contributors to run `SHRINKRAY_SMOKE=1 uv run pytest tests/test_smoke.py -v`, which inherits the suite-wide coverage floor and always exited 1 (about 11% coverage from one file) even with every smoke test green. The command now carries `--no-cov`, matching CONTRIBUTING.md.

- **ui/AGENTS.md's gotchas name only things that exist** (issue #294): the "Two dead surfaces" bullet described symbols removed by #239 (`requestEncodeAll`, the preflight-only-CLOSE ceremony, the inert Overview CANCEL) — each verified absent from the UI code on `main` before removal (`requestEncodeAll` has no match; only stale comments still mention the preflight); the hardcoded-defaults and shortcut-legend notes stay (both verified true, the legend mismatch marked as real).

- **A library below a folder named `.shrinkray-*` is visible again** (issue #286): the staging filter checked the ABSOLUTE path, so any ancestor above the library whose name starts with `.shrinkray-` (say `/mnt/.shrinkray-archive/library`) made every movie in it invisible to the scan and the watcher; the predicate now scopes the prefix check to the walk root, and the staging folders themselves (below the root) are still filtered. Both walkers pass their root.

- **SECURITY.md describes the server that exists** (issue #288): the posture section still said "no authentication" and named a `POST /api/duplicates/delete` route from a removed subsystem; it now describes the real model (the token from `$SHRINKRAY_TOKEN`, the loopback default, the public-bind refusal, the container's generated token from #267), the actual route list (twelve GET, one capability-gated POST), the middleware's cannot-add-unauthenticated guarantee, and the terminal as the control surface. The stale `validate_path` module path is corrected.
- **The watcher's changed-file test no longer depends on the filesystem's clock tick** (issue #302): inode mtimes are quantized to the kernel's tick (~10 ms on WSL2 and loaded CI runners), so `test_watch_queue`'s two same-size writes inside one tick produced an identical mtime and the identity check reported the rewritten file as already known, an intermittent failure on unchanged code. The test now changes the file's size (the deterministic half of the identity) and names the quantization: 2 failures in 3 class runs under Python 3.10 before the fix, 0 in 100 after.
- **The watcher is a thin loop over the job queue, and the database is its memory** (issue #231): the watch loop was a second engine — it wrote no database rows (no scan, no verdict, no encode), kept its "already decided" set in memory so every container restart re-probed the whole library, never retried a failed encode, and never verified. The watcher now scans every stable new or changed file into the database itself (the contract's first half) and hands the file to the SAME queue the boot backlog uses through a `submit` seam the app injects (the engine layer cannot import the server layer); the encode job owns plan-consulting, gates, encoding, its own row, verification and retry. `known` seeds from the `files` table's mtime+size (what a scan decided from), so a restart resumes instead of re-probing, and a changed file is a new question exactly as the contract says. A stateless `watch()` call (tests, one-shot runs) keeps the direct path.
- **The boot backlog's encode job runs instead of crashing** (issue #192): `auto_backlog` enqueues the encode with `{"paths": [...], "quality": True}` and no output directory, and `execute_encode` indexed `payload["output_dir"]` unconditionally — in the container (the only deployment where `app.auto_backlog` is on) the boot backlog ran scan -> plan -> **encode crashed with `KeyError: 'output_dir'` on every start**, leaving a standing failed job in the dashboard while the watcher thread did the real work unrecorded. A missing `output_dir` now means the in-place form, the same contract the CLI documents: the encode lands in a working directory inside the scanned root, and a verified output takes the source's own path with the original renamed aside and kept. The swap is one code path for CLI and job worker (`service.swap_encode_into_place`, extracted from the CLI so the layers stay clean); a declined swap reports an honest skipped outcome instead of crashing, and an explicit `output_dir` in the payload keeps the two-directory form unchanged.

- **The in-place staging directory is never a scan candidate** (issue #237): the working directory an in-place run encodes into is created INSIDE the library (the swap's renames must stay same-filesystem), and the encode it holds is named like the movie it will become — so `find_movies` and `find_new_movies` both treated an in-flight or crashed run's output as a library movie: a SIGKILLed run left a permanent phantom the next scan recorded, a concurrent SCAN job probed a file that was still being written, and the watcher could pick up its own in-flight encode as a new arrival. One predicate (`replace.is_staging_path`, beside the two names it filters) is now applied by both walkers, so the scans cannot drift apart again.

- **The encode slot is keyed on the contended directory, so in-place encodes are mutually exclusive for the first time** (issue #230): a height-only floor skipped exactly the widescreen sources this product exists for — a 2.39:1 scope film is a 1080p-class master at 1920x800, and the gate rejected it as "too few pixels" while admitting a 1440x1080 anamorphic file. The gate is now one predicate (`is_1080p_class`: width >= 1920 OR height >= 1080, either dimension at class size qualifies, an unreadable probe is never a skip) applied identically by `plan` and `encode`, with a new `eligibility.min_source_width` floor that follows the same raise-only rule as the height floor. The codec gate is now one whitelist (`SOURCE_CODECS`: h264, hevc, vp9, av1) instead of two constants whose names described the abolished bars-only rule; config extends it and can no longer shrink it, and the skip message names the actual rule instead of the false "below the h264 minimum" (which read as "older codec" for a VP9 source).
- **The audit trail records the artifact's real location** (issue #232): every in-place encode wrote a row whose `output_file` pointed at the per-run staging directory the run then deletes — so `doctor` reported "encode output vanished" for every swap on a healthy library, the generation chain never linked (an in-place re-encode was always generation 1), and an interrupted batch re-encoded everything it had finished. The row now records the path the artifact occupies after the run (the source's own path in place), a declined swap clears the row (the encode is discarded with its staging directory, and a refusal is the healthy case), `finished_movies` resumes from the recorded path, and the watcher records its outcomes at all for the first time (through a record callback the app passes in — the engine layer cannot import the service layer).
- **The install story tells the truth about the toolchain** (issue #241): the README's Linux section sent users to `apt install ffmpeg` (Debian/Ubuntu's build has no libvmaf, so the CRF search cannot measure a single file) and `apt install handbrake-cli` (Ubuntu 22.04 ships 1.5.x, below the 1.6 floor), the prerequisites table called HandBrake "optional" and libvmaf a Windows-only concern. A Requirements block now states the two hard requirements up front with `shrinkray doctor` as the check; the Linux section names the container as the recommended route and gives working static-ffmpeg + source-build instructions for bare metal; and `doctor` runs the toolchain check WITHOUT a database (a fresh install had no scan to point at, and the db check fired first), printing that the library check is skipped and exiting non-zero only on real toolchain problems - the problems are echoed to the terminal, not only the log.
- **Encodes run again: the codec gate always applies the product whitelist** (issue #271): #265 made `eligibility.candidate_codecs` the operator's *extra* codecs (empty by default), but every entry point still handed that list to the gate as the *whole* candidate list, so with the default config the CLI, the resident watcher and the backlog jobs skipped every source as `source codec 'h264' is not in the candidate codec list ()`. The gate in `plan` and `encode` now accepts `SOURCE_CODECS` (h264, hevc, vp9, av1) plus the configured extras, so no caller can shrink or replace the whitelist, and an empty extras list is valid again in `config.json`.

- **The resolution gate is the 1080p class, not "1080p tall", and VP9 is a candidate codec** (issue #233): a height-only floor skipped exactly the widescreen sources this product exists for — a 2.39:1 scope film is a 1080p-class master at 1920x800, and the gate rejected it as "too few pixels" while admitting a 1440x1080 anamorphic file. The gate is now one predicate (`is_1080p_class`: width >= 1920 OR height >= 1080, either dimension at class size qualifies, an unreadable probe is never a skip) applied identically by `plan` and `encode`, with a new `eligibility.min_source_width` floor that follows the same raise-only rule as the height floor. The codec gate is now one whitelist (`SOURCE_CODECS`: h264, hevc, vp9, av1) instead of two constants whose names described the abolished bars-only rule; config extends it and can no longer shrink it, and the skip message names the actual rule instead of the false "below the h264 minimum" (which read as "older codec" for a VP9 source).
- **One unreadable file no longer stops the resident watcher for good** (issue #260): a `RuntimeError` from the encode call's probe path (`ffprobe failed for '<file>'` — a truncated download, a file still being written, one corrupt file anywhere under the library) propagated out of the watch loop and ended the thread; the dashboard said "stopped" with no why, and the next container start died on the same file again. The per-file failure is now logged with the file's name and the watcher continues with the next candidate (the failed file stays in the known set — the retry question belongs to #231's failure memory); only a watcher-own failure (the staging folder unwritable, the root vanished) still ends the loop, visibly.

- **`python -m shrinkray` works** (issue #262): the module form imported the commands and stopped — exit 0 with no output, because `__main__.py` defined the typer app but never called it; a script running `python -m shrinkray encode ...` believed it had encoded. The `if __name__ == "__main__": app()` guard is in, the console script's behavior is unchanged, and the test runs the module form via `sys.executable` and asserts the five commands render.

- **The 1080p resolution floor can no longer be configured away, and `plan` applies the eligibility gates** (issue #246): `eligibility.min_source_height` below 1080 (including `0`, which used to switch the gate off) is now rejected when the config loads, with a message naming the rule; raising it (e.g. `2160` for 4K only) still works. The engine's own default is the 1080p floor instead of `0`, so a caller that omits the argument gets the rule rather than disabling it. That omission was live in the `plan` command, which passed none of the three eligibility gates: it probed and recorded plans for sub-1080p, below-size-floor and old-codec sources that `encode` then skipped, and a raised floor in `config.json` never reached it.
- **A 10-bit SDR source keeps its 10 bits** (issue #234): the encoder choice was `encoder_for(hdr)` — an HDR guess — so any SDR source encoded 8-bit, even one mastered as `yuv420p10le` (anime, grain-heavy films), which bands gradients and produces a worse file than the source on the exact path the product exists for. The probe now reads the stream's real bit depth (`bits_per_raw_sample`, falling back to the `pix_fmt` name), the choice is `encoder_for(bit_depth, hdr)`: any 10-bit source gets `svt_av1_10bit`, an 8-bit source stays 8-bit, HDR keeps its override, and an unknown depth falls back to the HDR answer instead of silently truncating. The depth is carried on the snapshot, the `QualityResult` and the encode row (schema v17, `source_bit_depth`); the plan fingerprint already keys on the encoder, so stored plans re-probe once per 10-bit source — the deliberate cost of the decision.

- **The release workflow parses again** : the gate step's name introduced with the gate-script change carried an unquoted `: ` inside the YAML mapping value, which made the whole workflow file unparseable — GitHub registered that as a startup failure with zero jobs on every push to any branch (8 consecutive red runs), and the next `v*` tag release would have failed the same way. The name now uses a dash; every workflow file and the compose file parse clean.

- **The published container sees the common video containers, not just `.mkv`** (issue #204): the image's baked `config.json` now sets `file.extensions` to `.mkv`, `.mp4`, `.m4v`, `.avi`, `.mov`, `.ts`, `.m2ts`, `.webm` — before, the code default (`.mkv` alone) made a mounted `.mp4` library scan nothing while `scan`/`encode` still exited 0. The README states the narrow code default explicitly.

- **`plan` exits 1 when nothing could be planned** (issue #203): `encode` already failed loudly on an unusable toolchain; `plan` rendered the identical failure as an error row and exited 0. Now an all-error plan is a failed command, a plan with results alongside error rows still succeeds (a partial answer is an answer), and an all-skipped plan stays at 0 (a skip is a decision, not a failure).

- **`plan --no-table` prints the plan without the rich table** (issue #201): `scan` already had the flag for scripted runs; `plan` — the other read-only, scripted command — now accepts the same `--no-table` (no box-drawing characters or ANSI codes in a pipe), while the summary line and the `--db` plan cache keep working unchanged.

- **`scan` fails honestly when every file failed to read** (issue #196): the run guarded its output on the FOUND list, so an all-error scan exited 0 and wrote a fabricated report (`Total;None;0` in the CSV). Now the outputs (table, `movies.txt`, CSV) are written only when at least one file was read, an all-error scan exits 1 with a summary naming the count, a partial scan keeps exit 0 with its per-file errors, and the empty-folder case keeps its warning and exit 0.

- **A missing ffprobe/ffmpeg is reported as missing, not as "Permission denied"** (issue #195): on WSL a failed execve of an absent binary surfaces as `PermissionError [Errno 13]`, so the raw-OSError interpolation sent the operator to chmod a file that does not exist. `run_ffprobe` and `detect_vmaf_style` now catch `FileNotFoundError` (names the binary and the install action) and `PermissionError` (names the executable-bit cause) separately; every other failure keeps its old message.

- **The container docs no longer promise that a read-only library mount is safe** (issue #198): the paragraph attributed the container's behavior to `--replace`, a Mode A CLI flag the `shrinkray app` entrypoint does not have, while Mode B encodes in place and needs the mount writable — a read-only mount crashes the watch loop on its staging folder. The compose file and both doc examples now mount `/media` writable, and the docs state the real contract (in-place rewrite, original renamed aside as `<name>.shrinkray-original`, never deleted).

- **A filename containing `[` no longer breaks `scan`** (issue #200): any path with a bracket was treated as a glob, so an existing file named `with [BRACKETS] name.mkv` — the target library's common naming — was reported as matching no movie file. The resolver now treats `[` as glob syntax only when the path does not exist AND a `[`-pattern expansion finds files; a real file or folder with brackets scans exactly as named, and a nonexistent bracketed path still errors with "does not exist".

- **A one-file command touches exactly that file** (issue #197): all three commands (`scan`, `plan`, `encode`) resolved a named file to its PARENT folder and rescanned it, so on a flat library `encode a.mkv` batch-encoded everything beside it. `resolve_input_paths`' explicit file list now flows through `scan_movies`' new `files` parameter instead of being discarded; a folder still scans the folder, a glob still scans its matches, and the server's `resolve_movies` behavior (which already did this right) is now the CLI's too.

### Changed

- **The CRF search follows ab-av1's round structure and spends fewer rounds** (issue #313): the search used to probe the range's lowest CRF (14) upfront on every file just to detect an unreachable target. It now follows ab-av1's crf_search: the midpoint first, the 20%/80% point of the range on round two, the range's end on round three, interpolation once the target is bracketed; an unreachable target costs three rounds and the low end is probed only when the search heads there. An early stop accepts a passing CRF less than 0.1, 0.2, 0.4, ... VMAF above the target (doubling per round, ab-av1's formula); a probe below the target is never accepted. The trade: on simulated SVT-AV1-like curves a passing file takes 4.2 rounds instead of 5.9, and about one file in four ends 1-2 CRF steps below the best passing CRF (a slightly bigger file). Encode decisions change for newly probed files; stored plans stay valid (the plan fingerprint does not cover the search's shape).
- **HDR10 is no longer advertised as supported** (issue #358): the README and PRODUCT.md said "HDR10 is supported", a claim no measurement backed. Nothing about how an HDR source is handled changes — it is still encoded 10-bit and measured on tone-mapped SDR copies against the HDR target — but that measurement is an approximation (VMAF has no HDR model; #340 measured our scale ~2.9 below the reference tool's on one real pair, erring toward larger files), HDR10 metadata survival is not verified per file, and Dolby Vision is not handled (#104). HDR is now documented as processed, not guaranteed: check an HDR result before removing its retained original.
- **HDR10 is no longer advertised as supported** (issue #358): the README and PRODUCT.md said "HDR10 is supported", a claim no measurement backed. HDR is now documented as processed, not guaranteed: check an HDR result before removing its retained original.
- **The size decision at the chosen CRF reads every probe window's encoded bytes** (issue #314): the decision used to re-encode ONE 10-second window and ride on it - a dark static scene compresses far better (or a grainy one worse) than the film, so "is this file worth it?" was noisier than the probes the rest of the search pays for. The VMAF probes already encode every window; the cache now records each encode's byte count beside its score (a schema migration: old entries miss rather than mislead), and the chosen-CRF decision is the total encoded over the total sample bytes across all windows - ab-av1's estimate. A missing entry falls back to the single-window encode (a miss degrades to the old behaviour, never to a guess). The top-of-range bound probe stays a cheap one-window early exit.

- **Probe density is duration-based (`sample_every`)**: `quality.sample_every` (default 600s) and `--sample-every`/`--sample-count` derive the probe window count from the runtime, so coverage is a fixed fraction of the file (`sample_seconds / sample_every`) instead of shrinking as the movie gets longer (issue #14). An unreadable codec is probed rather than excluded: an unknown value must never silently drop a file the operator expected to be considered.

- **A minimum-size gate**: `eligibility.min_source_size_gb` (default 0, off) skips a source below the configured size with the reason `below min size`, before sample extraction or any probe encode (issue #19). It is off by default because the right floor is a property of the operator's library, not a universal truth: a 3 GB movie can still save 1.5 GB, and a 20 GB movie that is already efficient saves nothing.

- **A minimum-resolution gate**: `eligibility.min_source_height` (default 1080, matching the floor PRODUCT.md states) skips a source whose height is below it with the reason `resolution too low`, before any sample extraction or probe encode (issue #18). A lower-resolution source has too few pixels to save meaningfully, so the probe cost buys nothing, and the gate decides from cached metadata instead of a new probe. The gate is off when set to 0, and an unreadable height is probed rather than excluded: an unknown resolution must never silently drop a file the operator expected to be considered.

- **POSIX tree-kill via process groups** unblocks Linux CI; the tree-safe termination applies to every encode path.

- **The report creates its output directory and shows the verification column.**

- **AV1 is the only output codec**: SDR encodes with `svt_av1`, HDR with `svt_av1_10bit` (issue #21). x265 is gone from every path - not demoted to a fallback, not kept as an option. `encoder_for(hdr)` is the single source of the choice; the six HDR ternaries that used to be written per call site are replaced by it, and `handbrake.encoder` is a two-value assertion that rejects a config still naming x265 at load rather than silently producing H.265.

- **The thread cap reaches SVT-AV1 as `--encopts pin=N`**: `threads=N` is an x264/x265 option, and SVT-AV1's parameter parser silently ignores an unknown key. `pin` restricts execution to the first N cores, which is what the cap means here.

- **The decision statistic is the mean, not the minimum**: `probe_crf` aggregates the per-sample VMAF means with the mean instead of the minimum (issue #15). A minimum over samples is monotone non-increasing in the sample count: every window added can only lower it or leave it unchanged, which made it structurally hostile to the denser sampling #14 introduced - the better the coverage, the more likely one pathological window sank the whole score, pushed the search to the floor CRF and reported "target unreachable" for a film that was perfectly encodable. `achieved_vmaf` is now documented as the mean across probe windows, which is a better predictor of overall viewing quality; a user comparing runs across the change should know it is not the same statistic. What the mean gives up is stated plainly: "every probed window meets the target" is no longer literally true. Denser sampling makes a genuinely bad scene more likely to be observed and to move the average, but does not eliminate it.

- **A skip now carries its evidence**: `SkipEncode` carries the best CRF, the VMAF measured there and the probe count, and `save_skip` stores them on the encode row. Previously an `encode` skip dropped that evidence, so the next run could not tell "already probed at the floor and failed" from "never probed" and re-probed the same window every time.

- **A plan recorded under `min` is not reused as a `mean` one**: the aggregation is part of the plan fingerprint (schema v13), because a plan made under the minimum was a different decision. Existing rows default to `min`, which is what they actually measured.


- **`plan` extracts each probe window once instead of three times**: the sample windows are extracted up front and the same list is handed to the CRF search and to the reported size factor (issue #30). `find_optimal_crf_and_skip` used to extract its own copy for the search while `plan_quality` extracted a second one for the size estimate, and the size estimate used only the first sample of that second list, so every window was decoded and written more than once per plan. With the duration-based sample counts that multiplier applies to a larger base cost. A fresh `encode` extracted twice for the same reason.

- **The typing, lint and coverage bar is enforced, not aspirational**: every module under `src/shrinkray/` is now fully annotated and mypy runs with `disallow_untyped_defs`, `disallow_incomplete_defs`, `warn_return_any`, `no_implicit_reexport` and `strict_equality` (issue #40). `py.typed` ships in the wheel, ruff runs the `S` (bandit) rules with each exception carrying its reason, and coverage has a floor so a regression fails instead of sliding. The per-module mypy rollout list is gone: one config applies to all of it.

### Fixed

- **A stall watchdog that killed healthy encodes**: piped HandBrake never sends newlines, so the newline-based liveness check starved and killed running encodes; the watchdog now reads progress correctly and stall telemetry reaches every encode path.

- **The encode result survives an absent ffmpeg** (CI run 160): version metadata probing is guarded, so verification metadata never fails an encode.

- **Watch mode's recursive/liveness traps** fixed, with prompt app shutdown on stop.

- **UI fixes**: readable primary hover; the two audit trails link to each other; a job trail shows the movie's own outcome inside a batch job; signed colored deltas, one unit spelling, one VMAF precision; drift chart geometry was lying (real pixels, labeled lane, visible marks); drift summary crashes; derived out-bars dressed as measured; `driftW` declared before use.

- **Test-suite fixes**: the test_db job import follows the server/ move; the `logs/` telemetry-leak fix (a verify run without a db file no longer writes failure bundles into the working directory, `tests/test_telemetry_leak.py` pins it); the CodeQL sanitizer follows the server/ move (issue #55).


- **Probe samples were re-encoded with lossy libx264**: sample extraction now stream-copies the source (`-c:v copy`, keyframe-aligned, timestamps normalised with `-avoid_negative_ts make_zero`) instead of running a CRF 12 x264 pass (issue #16). The samples are both the VMAF reference and the probe encode's input, so the re-encode biased every measurement: it smoothed grain and fine detail, which made the probe source easier than the real one and pushed the chosen CRF too high. The copy also keeps the source's bit depth, colour tags and HDR side data, which the x264 pass dropped. If a container cannot hold the source codec the extraction falls back to a lossless `ffv1` re-extract and logs that it did, rather than silently encoding lossily.

- **A batch encode's live progress was silently dropped**: `encode_movies` rebound its `progress` parameter with its own rich progress bar, so a resident app job never streamed a percent for a fixed-preset batch. The caller's callback now receives every event alongside the bar.

### Removed

- **The orphaned PosterCard component and its design tokens** (issue #180): `PosterCard.svelte` was created in the round-2 redesign, demoted (DESIGN.md's own note: 354 near-identical typographic tiles differentiated state but not identity), restored by accident, and never wired into a page. Gone together with the unused `--poster-ground` / `--poster-line` tokens; DESIGN.md's section is marked historical. Recoverable from git history if the poster grid ever returns.

- **Duplicate detection and the only destructive route**: `dedupe.py`, the `/api/duplicates` read route, `/api/duplicates/delete`, the Duplicates page, the `dedupe` job kind, and the `send2trash`/`rapidfuzz` dependencies are gone (issue #37). Deduplication is library management, which PRODUCT.md puts outside this tool's scope, and the delete route was the one code path in ShrinkRay that could remove a file from the library. A `metadata.db` that still holds `dedupe` rows keeps them as history: they read back as a generic `legacy` job, and a `queued` one is retired as failed at startup with the reason recorded instead of being executed.

- **Jellyfin integration**: the opt-in library-refresh notification after encode batches is gone (issue #43). ShrinkRay changes a file's bytes; telling another application about it is that application's job — and the integration was the only outbound network call in the codebase and an unauthenticated path to the process environment (any dashboard visitor could point `integrations.jellyfin.url` at their own host and exfiltrate any environment variable's value as a request header). A `config.json` that still carries the `integrations` key loads normally and logs one warning naming the removed key.

## [0.3.0] - 2026-10-22

The MetaDataScrapper era ends with this release: the tool is renamed to **ShrinkRay** and its purpose has grown from reading video metadata to a complete, quality-measured library shrinking pipeline.

### Added

- **Quality-measured re-encoding (the core feature)**: per-title VMAF-driven CRF search — short samples are probed at different CRF values, each scored with VMAF against its source, and a binary search finds the largest CRF that still meets the quality floor (default 95, roughly "transparent"); the movie is then encoded once with exactly that setting. Fixed-preset mode remains available.
- **HDR10 support**: tone-mapped (hable) VMAF measurement on both inputs, automatic 10-bit encoder switch (`x265_10bit`), calibrated HDR target and CRF range. Verified end-to-end on real content (The Mandalorian S01E02: 4.26 GB → 3.45 GB at full-movie VMAF 95.72).
- **Duplicate detection**: byte-identical (content hash), same-title and fuzzy-title grouping with duration gating; group summaries with wasted bytes; keep-rationale explains honestly why the best file is kept (byte-identical / highest resolution / highest bitrate / "no quality signal separates them"). DELETE moves files to the OS recycle bin (recoverable) and retires the row immediately; restored files recover on the next scan.
- **Resident app + web dashboard**: job queue (scan, plan, encode, dedupe) with live progress and per-movie fractions, adaptive polling snapshot API (one round-trip, ETag-cached library), provenance chain per title, config editing from the UI.
- **Generation tracking (schema v7)**: every encode records input/output bitrate, source/output paths and its generation number; re-encoding an encode chains automatically. `shrinkray compare` renders a title's provenance chain (the generation-drift ledger).
- **Resource politeness**: encodes, probes and VMAF measurements run below normal priority (config: `resources.idle_priority`); per-encode thread cap (`handbrake.max_threads`, CLI `--threads`); the resident app logs its own memory every 5 minutes and exposes `rss_mib` in the status API (measured: ~16-64 MiB resident).
- **Concurrent encode guard**: a pid-stamped lock file per output directory makes encoder collisions (job worker vs watch loop vs CLI) impossible instead of unlikely; stale locks of dead processes are stolen.
- **Opt-in Jellyfin integration**: one fire-and-forget `POST /Library/Refresh` after encode batches (token via environment variable, never in config.json).
- **Soft-missing reconciliation (schema v6)**: deleted files are flagged and hard-deleted only after 3 consecutive missing scans; reappearing files recover automatically; mass-flagging emits an accident warning.
- **Failure evidence bundles**: failed VMAF measurements and encodes bundle command, stderr (empty recorded explicitly), traceback and artifacts into `logs/` for diagnosis.
- **Windows installer**: `install.ps1` one-liner (uv, GPL ffmpeg with libvmaf, HandBrakeCLI, repo, dashboard build; idempotent).
- **Linux/NAS deployment**: verified end-to-end on Ubuntu (WSL rehearsal): full gate, VMAF measurement, headless recoverable trash, graceful HandBrake absence, POSIX niceness and `/proc` RSS; systemd unit in `deploy/`, README Linux/NAS section.

### Changed

- Rename MetaDataScrapper → ShrinkRay (package `src/shrinkray/`, CLI `shrinkray`, GitHub repo). All tool configs, ignores and docs swept.
- Scans are deterministic on every filesystem (sorted output; os.walk order is hash-ordered on ext4).
- Encode results are recorded benchmark-grade (schema v5): source snapshot, CRF, VMAF, probe statistics, tool versions.
- Duplicates API and UI exclude retired/missing rows.

### Fixed

- Same-thread db locking crash ("cannot release un-acquired lock").
- Live progress deadlock: subprocess pipes are drained concurrently while streaming stdout.
- Encode truncation: outputs are duration-verified, not trusted by exit code alone (HandBrake can exit 0 on failure).
- Path allowlist hardened (realpath + containment; traversal rejected).
- `os.startfile` guarded so mypy's linux view passes CI.
- Test suite uses real temp directories (fictional `D:/...` paths broke scope containment on Linux); scan order determinism; rename leftovers in tool configs (coverage target, first-party lists, gitignore model path).

### Security

- Supply-chain hardening: uv malware-check gate, 7-day new-package cooldown with security-fix exemption, CodeQL-recognized path sanitization.
- No secrets in tracked files: integration tokens live in environment variables by construction.
